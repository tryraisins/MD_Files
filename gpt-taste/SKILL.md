# GPT Taste compatibility route

`gpt-taste` is retained so existing prompts and projects do not break. Its former recipe forced the same AIDA structure, Python-randomized layout, gapless bento grid, massive spacing, and GSAP treatment regardless of product context. That produced deterministic novelty rather than design taste.

For current work:

1. Apply `high-end-visual-design` when the user explicitly wants premium, agency, editorial, experimental, or showcase-level art direction.
2. Apply `design-taste-frontend` for expressive general frontend implementation.
3. Apply `ui-quality-baseline` to every visible output.
4. Use `design-reference-research` when the direction needs live reference study.

Preserve an existing project's deliberate AIDA, bento, or GSAP implementation when the user wants it maintained. Do not introduce those patterns merely because this compatibility skill was named.
